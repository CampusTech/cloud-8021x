# Fixed NAS input producer

`task11-scenarios prepare [--dry-run] [--debug]` has no positional arguments, stdin input, path, plan, node, endpoint or authority overrides. This is a development-only root ARM Linux action inside the enrolled synthetic outer node. It requires the protected fixture marker and actual executing helper SHA/inode, reads only fixed protected inputs, and checks the actual protected app executable hash. Dry-run performs those read-only checks and returns public input/plan hashes; it creates no files, keys, attempts, processes, sockets or product state.

Before this command, the genuine `task11-acceptance seed` and fixed `task11-assembly-seed finalize` must have completed, the platform must have assembled its independently pinned seven helpers/NAS root, and the real `keys` stage must have frozen the four physical nodes. The producer reads `control/original-seed/{assembly-input.json,original-manifest.json}`, `control/{platform-inventory.json,platform-plan.json,enrollment.json}`, the exact closed original20/NAS input files, and four staged config candidates at `roots/task11-ROLE/var/cache/cloud-8021x/artifacts/config.yaml`. The assembler stages the same proposed green role configuration into blue and green: staged Hostname, Class path, deployment and collection epoch must match the green role. All four staged Deployment receipt keys must pass shipping ValidateHandoffPins and equal the four final physical enrollment keys; the source deployment/instance names remain closed. Blue physical enrollment remains independently blue, and its separately installed source configuration is not the staged artifact. All files are bounded, root-owned, no-follow, single-link and mode0600; ancestors must be safe. Input bytes, including whitespace, are preserved and hashed directly.

Original provenance is the final original20 manifest SHA, as independently enrolled. The finalized assembly-input raw SHA is independently bound by platform inventory/plan; its Files map separately binds original EC client bytes and the pre-generated NAS inputs excluded from original20. API version1 values, not a credential recreation or API permission state, supply the shared RADIUS secret, broker token, Class credential and public RSA decrypter. The fixed original RADIUS SAN is radius.task11.test. Actual shipping config decoding confirms fleet:1/task11 VLAN120, numeric Wi-Fi NAS .40/32, the fixed broker URL and the explicit configured green collection epoch. The original fingerprint cache independently confirms the original client UUID, fleet:1 group and frozen observation timestamp. No server result is used to choose expectations.

The seed finalizer generates exactly one persistent synthetic client PKCS8 RSA2048 key before finalized Input.Files, fixed EAP config and exact credential copies. NEW radius-task11-secret is generated with the already-required task11- prefix before its version1 publication; preserved original EC, Class, CA/config/cache/certificate-state bytes are unchanged. Authority/KMS private keys never become NAS materials.

Publication uses the fixed private NAS backing `aux/nas/var/lib/cloud8021x-task11-nas` (NAS view `/var/lib/cloud8021x-task11-nas`): root0700 and exactly thirteen root0600 files: eap.conf, radius-secret, class-key, client.pem, client.key, ec-root.pem, ec-intermediate.pem, rsa-root.pem, rsa-intermediate.pem, rsa-decrypter.pem, broker.crt, broker-token, scep-client.key. rsa-decrypter.pem is a PUBLIC certificate. No CA or Cloud KMS private material is copied. Files match the plan's exact byte digests; all nine cases retain the same client key/source identity.

Plans publish exclusively under `control/scenarios/plans`: native-accounting.json, ongoing-interim.json, ongoing-stop.json, duplicate-pair.json, ha-primary.json, postgres-outage.json, business-outage.json, ca-ec-continuity.json and ca-rsa-continuity.json. Sessions are distinct fixed task11-CASE values; Class and resulting event/usage IDs remain genuine runtime measurements. Statuses/counters and five-second outages are preselected. HA independently targets secondary. CA authority derives from its exact basename; original EC8443 and RSA8444/wifi-scep route to blue-primary, broker9081 TLS name localhost. Both CA phase plans bind the same immutable physical enrollment and explicit collection epoch; real issuance selections/results are generated only later. A placeholder START event in CA plan satisfies the existing closed plan schema but is never credited/sent as CA proof.

`control/scenario-preparation.json` is an exclusive input identity claim containing only input/plan digests/counts, never readiness, signatures, product activation or a pass marker. Creation precedes exclusive private directories/writes; any existing destination or partial write refuses, preserves previous/foreign bytes and blocks retry. All validation precedes this irreversible claim. A completed preparation also refuses regeneration. The parent must explicitly reconcile an uncertain publication; there is no repair/delete/resume flag. The producer creates no irreversible traffic attempt: the separate reviewed run command owns those only after actual readiness.

Source tests use real in-memory synthetic certificate chains and temporary directories, not installed helpers or fabricated product results. Fresh helper builds, real seed/finalizer/keys/assembly/publication, NAS mount/namespace/executable checks, genuine EAP/CA issuance, SQL continuity/replay and decoded intake acceptance remain separate required actual gates.
