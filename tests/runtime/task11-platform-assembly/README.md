# Private Task11 platform assembler

Development source only. No platform operation has been executed by this slice.
The builder reports R161's minimal actual347/empty-audit canary passed its
nested PID1/namespace/loop/reboot sequence and retired. That separate receipt
must be reviewed; its copied lower is not this assembler's sealed package layer.
Post62 footprint, exact device exposure, capacity, four-node assembly, primitive
and full installed-workflow gates remain separate. No retained canary disk is
implicitly admitted as a reusable assembly base.

This is a real guarded installer, not a readiness generator. It calls only fixed,
independently pinned tools, uses actual package installation with starts blocked,
and stops on any uncertain partial operation. No product bootstrap, activation,
CA identity, collector allocation, receipt or accounting row is invented.

## Fixed inputs and admission

The caller independently pins root0600
`/var/lib/cloud8021x-task11/control/platform-plan.json` with `--plan-sha256`.
Strict JSON uses the exported `plan` field names. There is no root, endpoint,
command, image, namespace, destination or credential override. `Schema` is1.

- `InputSHA256`: finalized `control/original-seed/assembly-input.json`, with all
  original byte pins validated by the shared seed contract and no freshened time.
- `CandidateSHA256`: `control/runtime-candidates/candidate-index.json`; closed
  file destinations, owner/group/mode, hashes and exact public references.
  Runtime candidates must already use these fixed guest source paths. This
  installer never rewrites a candidate index or its source references.
- `PackageManifestSHA256`: `control/public/artifacts/package-manifest.json`,
  shipping validator/62 exact ARM64 archives and all archive byte hashes.
- `ApplicationSHA256` and clean40hex `ApplicationSourceSHA`: actual LinuxARM64
  shipping build metadata, with no dirty-tree substitute.
- `Helpers`: exactly task11-acceptance, task11-passive-audit,
  task11-cloud-contract, task11-assembly-seed, task11-blue-migration,
  task11-systemd-fixture and task11-scenarios. Each `{path,sha256}` is fixed
  to `control/public/NAME`.
  Controller/observer/cloud hashes also bind the candidate enrollment. The cloud
  binary must remain reviewed `e6c0a5373ca718e17cf288f28095223c67dbfefa88461233ed1660ec2d5fd0d4`.
  Helpers are development binaries; only the shipping app is called a clean build.
- `ControllerUnitSHA256`: exact independently reviewed
  `control/public/task11-acceptance.service` bytes from the controller source.
  They are installed without changing its delegation/cgroup contract.
- `ObserverSourceSHA256`, `CloudSourceSHA256`, `PrimitiveSeedSHA256`,
  `PrimitiveInputSHA256`, `PrimitiveExpectedSHA256`, `BluePlanSHA256`: exact
  independent receipts/input pins, not execution evidence. Blue migration plan
  is fixed `control/blue-migration.json` and is consumed unchanged.
- `Tools`: exact paths defined in `toolPaths`, each with independently reviewed
  actual guest executable SHA. No private download, shell command or mirror.
- `BaselineSHA256`: actual bytes from the documented dpkg-query expression in
  `preflight`, exactly347 lines. The genuine pinned systemd-fixture
  `prerequisites --final` additionally verifies its321+26 identities and empty
  audit using the existing reviewed `/run/task11-media` input set.
- `LowerManifestSHA256`: independently reviewed root0600
  `control/lower-source.json`. Schema1, ordered or unordered `Entries` with
  `Path`, `Kind` (file/directory/symlink), permission `Mode`, exact file `Bytes`
  and `SHA256`, or exact symlink `Target`. Maximum200000 entries/32MiB metadata,
  maximum1.625GiB file stream. This is a public package projection of the actual
  admitted base. Private identities, seed/control/SQL/log/runtime trees and
  machine/SSH/authentication material are excluded; public targets of symlinks
  are checked and links are never traversed while copying. Every copied file
  is independently pinned; absent required package files cause a real refusal.
- `Nodes`, `Flows`: the exact four ordered nodes and closed address/protocol/port
  graph in `fixedNodes/fixedFlows`, with four distinct32hex machine IDs.
- `LoopDevices`: two distinct independently measured exact loop device paths.
  Both green units expose that same pair plus loop-control, never the loop major
  or all of `/dev`. These fields do not reserve devices.
- `Budget`: independently measured source/lower/staging/private bytes and inodes,
  current available bytes/inodes. Source <=1.5GiB, copied/post62 lower <=1.75GiB,
  staging <=512MiB/private inputs <=128MiB, and conservative backing/reserve
  arithmetic. Existing staged inputs are already deducted by the actual statfs
  measurement and are not charged a second time. ext4 uses explicit nodiscard
  after fallocate so formatting cannot punch out the backing reservation.
  Actual guest free capacity must satisfy the supplied measurement.
  Insufficient space is a blocker, never a reason to resize product storage.

The initial operation requires actual Linux effectiveUID0, root0644 marker
`/etc/cloud8021x-task11-fixture` containing `synthetic-only-v1\n`, actual outer
systemd PID1, no container marker, physically zero NICs, and only loopback.
Existing assembly roots/foreign interfaces are refused. Inputs use no-follow
protected ancestry, bounded single-link private inputs/helpers, exact pins and
exclusive output. Public baseline hardlinks alone may be copied into independent
lower files, with checked mode/size and a second streaming hash; no alias enters
a private output.
The exclusive operation lock serializes stages; each stage also leaves a durable
exclusive attempt file. A failed stage cannot automatically replay. Inspection
and a separately reviewed fresh attempt are required; there is no cleanup flag.

`--dry-run` checks identity and protected inputs without any child process,
connection, lock creation or write. `--debug` logs public counts only. Operation
errors omit private values. Real child operations have bounded output, deadlines
and process-group cancellation. No operation under this source grant was run.

## Later separately authorized order

After the actual321+26 prerequisite check, `task11-platform-assembly measure-base`
records the actual347-row query, empty audit, 14 canonical executable hashes,
bounded public lower projection with exact Unix modes, current statfs and existing
loop occupancy. It exclusively publishes root0600 `control/base-after-prereqs.txt`,
`control/lower-source.json` and `control/base-observations.json`; partial or prior
outputs refuse replay. Symlinks are recorded without following targets, and private,
excluded and special files are never opened. Free loops and space are observations,
not reservations or readiness. Later staged inputs require a fresh capacity check.
`measure-base --dry-run` prints its fixed plan without filesystem or process access;
it accepts no path, root, tool or endpoint override and needs no platform plan.

```text
task11-platform-assembly assemble --plan-sha256 PIN
task11-platform-assembly start-primitive --plan-sha256 PIN
```

`assemble` verifies actual baseline and audit, creates the bounded common ext4
lower, copies the public projection, installs actual62 packages in fixed transient
`task11-lower-install.service` (owned RootDirectory, PrivateDevices/MountAPIVFS,
PrivateNetwork, bounded memory/tasks/time, closed public archive directory mounted
read-only), with policy-rc.d
refusing starts, audits and measures the result, removes generated shared private
state, and remounts it read-only. Blue overlays alone create shipping runtime
accounts/groups; green runtime accounts/config publication remain product work.

Private backing ceilings are768MiB per green,256MiB per blue,256MiB PostgreSQL,
128MiB API and64MiB NAS. Both real512MiB product collector images must fit inside
those green overlays. No image is preseeded. Public archive/application/helper
files use individual read-only binds, while incoming config/CA/proof/receipt-key
locations remain private writable. Post62 and private write footprint plus the
>=1GiB free reserve must actually fit; source calculations alone do not prove fit.

The unaddressed bridge is `c8021x11`. Fixed source-preserving namespaces are
`c11-bp/.31`, `c11-bs/.32`, `c11-gp/.21`, `c11-gs/.22`, `c11-api/.10`,
`c11-pg/.11`, `c11-nas/.40` on10.203.11.0/24. Each node has its own
169.254.169.254 loopback metadata service/seed/journal. There is no NAT, uplink,
forwarded-identity substitute, default route or external DNS. Guest hosts/trust
are local; the Mac's trust/network are never touched. Deny-by-default bridge and
namespace rules precede link activation. Only actual known business OTLP intake
is mapped; ordinary Datadog intake is not silently widened.

Assembly installs units but starts none. Node units are
`task11-node-ROLE.service`; registered names `task11-ROLE`, roots
`/var/lib/cloud8021x-task11/roots/task11-ROLE`. They use actual nspawn boot and
`--keep-unit`; v257's documented `SuccessExitStatus=133` and
`RestartForceExitStatus=133` pair handles a managed reboot, with `Restart=no`
for ordinary failures. Source/green package services remain disabled initially.
The initial node boot starts only the distinct metadata service.

The separate actual primitive driver runs in the private API namespace, with its
existing fixed pins/arguments from assembly-seed. It must write a genuine
`control/primitive-api/verified-result.json` from actual SDK/adapter traffic and
frozen cloud verification. The operator independently pins those exact bytes.
Platform does not call or synthesize that driver during assembly.

```text
task11-platform-assembly start-original --plan-sha256 PIN \
  --primitive-result-sha256 ACTUAL_RESULT_PIN
```

This rereads the protected primitive result, reruns the frozen real verifier over
the actual journal/state, requires equality, stops and observes the primitive
API inactive/PID0, then starts `task11-api-installed.service`. Separate gate roots
remain separately backed; server and outer fixed verifier see identical actual
private state. Primitive evidence cannot become installed-workflow evidence.

`task11-postgres.service` uses the generated PostgreSQL17 verified-TLS config,
private namespace and actual data. Fixed `task11-pg-{init,ready,roles}.service`
transients use the same PG-only namespace/root, real postgres user/group, private
API filesystems/devices and bounded time/control-group cleanup. Real initdb/psql
apply only the frozen role/DB
SQL plan. The platform then boots all registered nodes without green product
services, invokes the real independently pinned blue migration in blue-primary,
and only afterward starts the reviewed blue policy/webhook/CA/native/writer
units. Green schema/epoch/receipts/credentials/activation are genuine later
product prepare/controller operations. Blue and green app databases stay distinct;
existing CA databases/signers and original observation timestamps stay unchanged.

`audit-loops --plan-sha256 PIN` inspects actual loop ioctl backing device/inode
identities and the actual first-free allocator. It permits either node to have
allocated first, but only exact512MiB root-private owned collector images. Run it
immediately before either activation and after reboot; current success is not a
reservation, product phase or kernel mount proof. No blanket device allowance is
used. Actual allocator/mount behavior still requires the later kernel gate.

NAS root is `/var/lib/cloud8021x-task11/aux/nas`; its existing pinned
`/usr/local/libexec/task11-systemd-fixture packets` and genuine eapol_test come
from the approved helper/base. The separate scenario owner supplies private NAS
inputs and independent expected projections. The seventh individually pinned
`task11-scenarios` helper is bound read-only at NAS
`/usr/local/libexec/task11-scenarios` alongside systemd-fixture.

Assembly explicitly mounts procfs at `aux/nas/proc` with
`ro,nosuid,nodev,noexec` using the pinned mount tool. Any preexisting target or
descendant mount, or nonempty/unsafe directory, refuses without repair or unmount.
Post-assembly and later reconciliation independently read bounded actual
mountinfo, procfs statfs/device and outer PID namespace, and retained
source/helper inode, SHA and read-only mount identities. This outer-PID proc view
is an explicit helper prerequisite, never a confinement claim.

Fixed `audit-nas --plan-sha256 PIN` repeats those read-only observations; generated
inventory alone cannot satisfy the audit. Root separately owns the 13 private
material publication and actual helper/assembly gates. None of these new
NAS helper/procfs operations has been executed by this source slice.

## Inventory ABI and limits

Root0600 `control/platform-inventory.json` uses strict snake_case:
`schema:1`, `plan_sha256`, `input_sha256`, `candidate_sha256`,
`nodes:[{name,machine,root,namespace,address,machine_id,config_sha256}]`,
`auxiliary:[{name,root,namespace,address}]`,
`helpers:{fixed_name:{path,sha256}}`. It reports only generated identities and
input pins. Config pins describe the original candidate; later authenticated key
configuration/enrollment has its own independent pins. There are no readiness,
receipt, activation or successful-reboot fields. Later stages compare this exact
inventory and observe actual mounts, namespace addresses and absence of default
routes; downstream controller/scenarios must independently inspect actual
registered PID1/root/cgroups/namespaces/services/boot IDs for their own gates.

Pure source tests cover rejected topology/pins/capacity, private input and output
substitution, closed candidate destinations, network rules, retained parent
bindings, startup order, managed reboot rendering, owned loop activation order,
and primitive/inventory evidence boundaries. They cannot certify nft kernel
syntax, loop ioctls, nspawn reboot, real package postinstall behavior, PostgreSQL,
service readiness or installed acceptance. All those actual gates remain open.

Binding grammar is taken from the pinned v257 upstream
[ExecStart parser](https://raw.githubusercontent.com/systemd/systemd/v257/src/core/load-fragment.c)
(lines851,957), [bind parser](https://raw.githubusercontent.com/systemd/systemd/v257/src/nspawn/nspawn-mount.c)
(lines220–258) and
[word parser](https://raw.githubusercontent.com/systemd/systemd/v257/src/basic/extract-word.c)
(lines62–107,130–145).
Literal Debian epoch colons require one escape through nspawn, and a separate
C-escaped quoted argument through ExecStart. The regression independently tokenizes both relevant parser subsets and preserves
the exact source and destination basenames, including
`datadog-agent_1:7.84.2-1+campus1_arm64.deb`. A unit token contains `\\:`;
the nspawn argument contains `\:`; its two decoded paths contain literal `:`. Kernel/runtime parsing remains a later gate.
